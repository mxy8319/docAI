# DocAI - 智能文档助手

> Next.js 14 + LLM + RAG + MCP 全栈 AI 应用
> 一站式文档解析、问答、摘要、知识库管理平台

---

## 🎯 产品定位

企业级智能文档处理平台，让非结构化数据变成可检索、可问答的知识资产。

### 一句话价值
> 上传任何文档 → AI 帮你读懂、总结、检索、问答、分析。

---

## 📋 产品需求文档

### 1. 产品背景

#### 1.1 问题定义

| 痛点 | 量化数据 |
|------|---------|
| **文档查找困难** | 找一份合同条款平均花费 23 分钟 |
| **信息提取低效** | 人工阅读 100 页 PDF 并提取要点需要 4 小时 |
| **知识无法沉淀** | 员工离职，文档里的经验也跟着走了 |
| **重复问答消耗** | 客服/HR 60% 的问题都是重复的 |

#### 1.2 目标用户

| 用户分层 | 典型场景 |
|---------|---------|
| **个人用户** | 研究论文、学习笔记、电子书管理 |
| **中小企业** | 合同审核、产品手册问答、员工手册 |
| **开发者** | API 文档解析、代码库问答、技术文档 |

### 3. 详细功能需求

#### 3.1 P0 - 文档上传与解析

**用户故事**：作为用户，我上传一份 PDF，系统自动帮我做向量化，然后我就能提问了。

| 验收标准 | 完成度 |
|---------|-------|
| ✅ 支持拖拽上传 PDF / TXT / MD / DOCX | - |
| ✅ 实时显示解析进度、分页预览 | - |
| ✅ 智能语义分块（不切断句子） | - |
| ✅ 支持 1000 页以上大文档 | - |

#### 3.2 P0 - 智能对话问答

**用户故事**：作为用户，我能用自然语言问文档里的任何问题。

| 验收标准 | 完成度 |
|---------|-------|
| ✅ 流式打字机效果输出 | - |
| ✅ 每个回答都带原文引用来源 | - |
| ✅ 支持多轮上下文对话 | - |
| ✅ 回答不知道的问题不胡说 | - |
| ✅ 点击引用跳转到对应页码 | - |

#### 3.3 P0 - 文档摘要生成

**用户故事**：作为用户，上传文档后立刻能看到这份文档讲了什么。

| 验收标准 | 完成度 |
|---------|-------|
| ✅ 上传完成自动生成摘要 | - |
| ✅ 3-5 个核心观点提炼 | - |
| ✅ 关键词、主题自动打标 | - |
| ✅ 可复制的结构化大纲 | - |

### 4. 技术架构方案

#### 4.1 技术栈选型

| 层级 | 技术选型 |
|------|---------|
| **全栈框架** | Next.js 14 App Router |
| **UI 组件** | shadcn/ui + TailwindCSS |
| **LLM SDK** | Vercel AI SDK |
| **向量数据库** | PGVector / Pinecone |
| **文档解析** | PDF.js / Mammoth |
| **嵌入模型** | BGE-m3 / OpenAI Embedding |
| **数据库** | PostgreSQL + Prisma |
| **认证** | Auth.js |
| **部署** | Vercel |
